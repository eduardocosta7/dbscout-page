DBScout Local Access Notice

Effective date: October 13, 2026

DBScout is a developer tool. To show you the databases of the apps you are building, it uses tools that are already part of mobile development — adb for Android, Xcode's devicectl for iPhone — and works with files on your computer and on your phone. This notice says exactly what it does, so you can decide whether to use it on a given computer, phone or project.

1. Nothing here is mandatory, and we are independent

  • You decide. DBScout only runs the tools below if they are on your computer, and it only downloads or configures one after you click. You can decline, uninstall them, or use your own copies. DBScout keeps working, with fewer features, without the optional ones.
  • These tools belong to others. adb and the USB driver are Google's, Xcode and devicectl are Apple's, the AI command-line tools are Anthropic's, OpenAI's and Google's. We have no partnership, sponsorship or agreement with any of them, and none of them guarantees, supports or is responsible for DBScout. We use them as any developer can, under the terms their owners publish, and those terms govern your use of them.
  • We do not control them. If an owner changes, restricts or discontinues a tool, a DBScout feature may stop working. We do not guarantee compatibility with any version.

2. What DBScout runs on your computer

Tool What for When
adb (Android Debug Bridge) List the connected Android phones, list the debuggable apps, copy their databases, write changes back While the app is open and a phone is connected; it checks for phones every 2 seconds
xcrun devicectl (macOS only) List the iPhone apps installed by Xcode or flutter run, copy their data container files, write changes back While the app is open and an iPhone is connected
xcrun simctl (macOS only) List the iOS Simulators that are running and find the data container folder of the apps installed in them by Xcode or flutter run While the app is open; it checks for running simulators every 2 seconds
The AI assistant CLI (Claude Code, Codex, Gemini) Answer the questions you type in the chat (Pro) Only when you send a question

DBScout prefers the adb you already have (Android SDK, Homebrew or PATH). It uses its own copy only if you have none and you clicked to install it.

All of these run as your user, without a visible terminal window, and only with the arguments DBScout itself builds.

3. What DBScout does on your phone

  • Android: it uses adb shell run-as <package>, which only works for apps installed as debuggable (debug builds). Release builds from the store cannot be read this way, and DBScout does not try to bypass this. It lists the files inside the app's own private folder, finds the SQLite databases by their file header and copies them, with their -wal, -shm and -journal companions, to your computer.
  • iPhone: it reads the data container of apps installed by Xcode or flutter run, through Apple's devicectl.
  • iOS Simulator (macOS only): the simulator keeps each app's data container in a folder on your Mac (~/Library/Developer/CoreSimulator/Devices/). DBScout finds that folder with simctl, reads the databases and the Library/Preferences/ file of apps installed by Xcode or flutter run directly from it, and writes changes (Pro) back to the same files. It only looks at simulators that are running, and only inside the data container of those apps.
  • Writes (Pro): when you edit a cell, delete a row, run a writing SQL statement, or let the AI assistant write, DBScout changes its local copy of the database and copies it back to the phone (or to the simulator's folder), replacing the app's database file.
  • App preferences: it reads the app's preferences files (shared_prefs/, files/datastore/, Library/Preferences/) and, when you save or delete one (Pro, Android only), closes the app (am force-stop) before writing. The app is not opened again by DBScout; you open it.

DBScout does not root, jailbreak, install anything on, or change the settings of your phone.

4. Changes that ask for your permission

Some components need administrator rights. DBScout asks the operating system, and only after you click:

  • Windows: the Google USB driver, installed with pnputil through the system's UAC prompt.
  • Linux: a udev rule that lets your user talk to Android phones, installed through pkexec.

5. Files DBScout writes outside its own folder

Only when you click to connect your editor's AI assistants to DBScout (extension), DBScout adds one entry named dbscout to their configuration files: ~/.claude.json, ~/.codex/config.toml and ~/.gemini/config/mcp_config.json. Nothing else in those files is changed. GitHub Copilot is connected through the editor's own API, without a file.

Exports (CSV, Excel, TXT) are written where you choose in the save dialog.

6. The local AI server

While DBScout is open, it runs a small server on 127.0.0.1 (your computer only) that gives AI assistants access to the databases and app preferences on screen. It needs a random token, created every time DBScout opens, and it cannot be reached from the network. On the free plan it refuses all requests.

7. Risks you accept

  • Writing to a database the app is using can corrupt it. If the app is running on the phone and writes at the same time DBScout copies the database back, one of the two writes may be lost or the file may be damaged. Close the app on the phone before editing, and keep a copy of data you cannot lose.
  • Saving or deleting a preference closes the app on the phone. Anything the app had not saved yet is lost, as when the system closes it.
  • Writes cannot be undone by DBScout, except for the copy kept before the AI assistant's first write in a session. Deleted rows are deleted.
  • What the AI reads goes to its vendor. See the Privacy Policy, section 3.7.
  • Two different versions of adb on the same computer stop each other's server. This is how adb works, not a DBScout defect.
